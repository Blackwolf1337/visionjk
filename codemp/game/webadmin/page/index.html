Physical props

Pick a model, then right-click on the map.
Every model is placed as a misc_prop with physics of its own: a body with the shape of the model that falls, tips, can be shoved, thrown, stacked and stood on. Thrown hard at somebody it hurts. It is in the list of the World tab afterwards.

Clips and walls

What stops players without being seen. The clips of the map are pink, the ones that are off red, the walls violet. A click on the map selects what is under the mouse. A wall is dragged with the mouse or sent to a spot with a right-click, its yellow handles drag one face each.
A clip is part of the map file every game has, so it can only be turned off, not moved. This game is told which ones are off and lets its player through. Another game still has the clip: it stops its player for a moment and the server then sets him right. Move it puts a wall where the clip was, which every game is told of. Nothing is kept until Save.

Texture swap

A shader of the map drawn as another one, for every player and at once. Every game can do that, the unchanged one too. A shader is swapped wherever the map has it, not on one wall, and a game only draws a shader it has. The surfaces that have the selected shader are yellow on the map, their rims faintly through the walls. A click on a row turns the camera to the nearest one.
The two pictures are the selected shader and what it would be drawn as. The ball or cube below them is drawn with that the way the game draws a shader on a model, with every stage of its script.
"Pick a texture" shows the textures of the game below the map. A click on one draws the selected shader as it at once, as a draft: only this page shows it, until Swap or Swap all sends it to every player.
A wall that is lit by a lightmap keeps its light in a game of this tree. Another game draws it without once it is swapped, and stays that way after the swap is taken back, until the map is loaded again. What is not lit that way is safe to swap: screens, signs, lights, the skin of a model.

Map

Bot route

The waypoints the bots walk along, in the order of the trail: yellow from each one to the next, blue to the others it leads to. A click selects one, Ctrl and a click one more or one less, Shift and a drag every one in a rectangle. Remove and Set flag are for all that are selected, and dragging one of them moves them all. With Add waypoint on, a right-click on the map puts a new one there, behind the selected one or at the end.
The bots stand still from the first change until the route is saved: which waypoint leads to which is only worked out again by the save, and so is the blue. Revert to saved drops what was changed since the last save, Map default puts back the route that came with the map.

server.cfg

The first save puts the file into the home path of the server (fs_homepath/<game>/server.cfg), which the engine reads before the one of the installation. The text before a save is kept as server.cfg.bak.
Running the file sets its cvars at once. Latched ones (most g_web*, sv_maxclients, the game type) take effect with the next map, and a line that changes the map does so.
The passwords in the file are shown as they are.

Bans

The addresses that may not connect (banIPs.txt of the server). A * stands for any number. "Ban" in the panel of a player puts his address here and kicks him, "Unban" lets an address connect again.

Token for scripts

A script sends it as "Authorization: Bearer <token>" and may do what this account may. It never gets the password.

One-time code for the game

Accounts of the panel

A moderator has the players (kick, ban, team and the like). An admin has the editor, the map and the log as well. An owner also has the console of the server, its config, its files and these accounts. A new account gets a password from the server, which is shown once.

Keys of admin_keys.txt

These keys log in to the game with "v_amkey login" and to this panel from the page of the login: rcon as an owner, council as an admin, knight and instructor as a moderator. The file is in the game folder of the server and is read with every map.

Server load

One value a second, the last five minutes of this map. A frame of the game is the step of the game module alone, with the work of this panel in it, which the second line shows by itself: answering a browser is done in a frame. Fewer frames than sv_fps or a long wait for one mean the machine does not keep up.

Server log

Game log is the log of the game as the server writes it: who came and went, kills, chat, the commands of admins. The whole file is games.log in the Files tab. Server console shows what the server prints on its console.
Intrusions is ids.log: what arrived that no client of the game sends, from which address, and which addresses were blocked for it (vs_ids). "vs_idsstatus" on the console lists the addresses, "vs_idsunblock" lifts a block.
All three start with their last lines and follow the text as it grows. A command typed into the line under the text runs as if it was typed on the server console, and the view goes to the console for its answer. The arrow keys up and down bring back the commands typed before.

Files

Server files is where this server keeps its configs, its logs and what is uploaded. A file there wins over the same file of the installation. Game installation is the game as it was installed and can only be read.
To add a map, drop its .pk3 on the list or use Upload, then use Restart map so that the server finds it. A .pk3 always goes into the top folder of the server files.
A click on a folder shows what is in it, a click on a text file opens it, any other file is downloaded. Game modules and programs can only be downloaded.
